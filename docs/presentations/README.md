# Prototype presentation

[Focal Prototype Presentation](<Focal Prototype Presentation.pptx>) is the editable class deck. It includes the problem and discovery findings, one hypothesis for each prototype, live-demo links, scope decisions, deliberate cuts, and a prompt for the class vote. Speaker notes contain the proposed timings, demo scripts, evidence sources, and limits of each experiment.

A second draft by Burak is in [burak-draft/](burak-draft/) (PDF, HTML and speaker notes). The two decks have not been combined yet.

## Suggested timing

| Slides | Section | Time |
| --- | --- | --- |
| 1–3 | Problem and how the team's thinking changed | 2 minutes total |
| 4–6 | A, B, and C hypotheses | About 2 minutes each |
| 7–9 | Live demos | About 2 minutes each |
| 10–12 | Prioritization, cuts, and next evidence | About 2½ minutes total |
| 13 | Class vote | 30 seconds plus voting |
| 14 | Backup demo links | Outside the main talk |

This is a proposed 17-minute sequence before voting. Rehearse and adjust it to the instructor's actual time allowance. Public app load time and C's physical setup can add time. Keep prepared demo tabs available and move on professionally if a live journey fails.

## Team handoff

- Edit the PPTX directly and keep the current filename so repository links stay valid.
- Confirm the team narrative, presenter handoffs, and proposed pilot thresholds. These thresholds are hypotheses rather than findings.
- Rehearse each demo twice and record actual runs in the [readiness checklist](../assignment-readiness.md).
- Run each public demo's main journey in a fresh session before class. The links are also recorded in the [deployment guide](../deployment.md).
- Submit the deck and all three public links to Canvas. The repository does not yet contain a submission confirmation or class vote.

The original discovery and strategy files remain in the [document library](../README.md). This deck summarizes existing evidence without changing the source workbooks or their team-written assessments.
